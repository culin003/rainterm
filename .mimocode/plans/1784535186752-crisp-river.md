# 主密码 + 自动锁定 实现方案

## 目标

1. **首次启动**：强制用户设置主密码（含确认 + 可选提示），不可跳过。
2. **后续启动**：显示解锁遮罩，通过密码验证后进入主界面。
3. **空闲自动锁定**：默认 600 秒，可在设置中调整（0 = 禁用）；活动 = 应用窗口内鼠标/键盘/滚轮事件。远程 PTY 输出**不**计入活动。
4. **手动锁定**：工具栏 `Lock` 按钮 + `Ctrl+L` 快捷键。
5. **锁定期间**：所有已建立的 `SshSession` / `SFTPClient` **保持连接**，仅 UI 被遮罩层遮住。**锁定期间禁止触发任何应用级快捷键**（含 `Ctrl+N` / `Ctrl+W` / `Ctrl+Tab` / `Ctrl+Shift+D` / `Ctrl+,` / `Ctrl+L` 本身等），用户只能在解锁面板输入密码。
6. **加密密钥派生自主密码**：Jasypt PBE 密码 = 由主密码派生的密钥。老数据一次性事务性迁移（用旧硬编码密钥 `raindrop-secret-key-2024` 解密 → 用新密钥重新加密）。
7. **忘记密码**：仅提供“破坏性重置”入口，需用户键入 `RESET` 确认，会清空 `credential` + `connection_profile` + 校验行。

---

## 关键决策要点（已与用户确认）

| 决策 | 选择 |
|---|---|
| 主密码与加密的关系 | **派生 Jasypt 加密密钥**（含一次性迁移） |
| 首次启动 | 强制设置，不可跳过 |
| 自动锁定默认值 | 600 秒；活动 = 应用窗口内鼠标/键盘 |
| 额外锁定触发 | 手动 Lock 按钮 + `Ctrl+L`（不实现最小化触发、不实现失焦触发） |
| 忘记密码 | 仅“破坏性重置”，无恢复通道 |
| 锁定 UI 策略 | **`StackPane` 遮罩**（不用 `scene.setRoot` 切换，避免 JediTermFxWidget 脱离场景图 / KDE 剥除最大化状态） |

## 2. 修改现有文件（方法级）

### 2.1 `src/main/java/com/raindrop/util/CryptoUtil.java`（全文重写，约 60 行）
- 删除硬编码 `SECRET_KEY` 与静态初始化的 `strong` / `legacy` 单例。
- 新增包内可见方法 `setActiveEncryptor(StandardPBEStringEncryptor)` / `clearActiveEncryptor()`（**仅** `SecurityManager` 调用）。
- 新增 `static StandardPBEStringEncryptor buildStrongEncryptor(String password)` 与 `static StandardPBEStringEncryptor buildLegacyEncryptor()`（`MigrationRunner` 用于解密旧密文）。
- `encrypt(String)` / `decrypt(String)`：若 active 为 null → 抛 `IllegalStateException("Crypto is locked")`。移除 `decrypt` 中的 legacy 回退（迁移完成后不应还有 legacy 密文；保留会掩盖 bug）。
- 15 处调用点签名不变；锁定状态下 UI 层已被禁用/遮罩，正常调用路径不会到达。

### 2.2 `src/main/java/com/raindrop/RaindropApp.java`（`start(Stage)`, 19–40 行）
- 在 `FXMLLoader.load(...)` 之后、`primaryStage.show()` 之前：
  1. 用 `StackPane sceneRoot` 包裹 BorderPane 根（`sceneRoot.getChildren().add(mainBorderPane)`）；`Scene` 基于 `sceneRoot`。
  2. `SecurityManager.getInstance().bootstrap()` — 读取 `master_password_verifier`，进入 `UNINITIALIZED` 或 `LOCKED`。
- `primaryStage.show()` 后：`Platform.runLater(() -> mainController.presentSecurityFlow(primaryStage))`。
  - `UNINITIALIZED` → 通过 `MainController.showAsModalDialog(setupStage)` 弹出设置对话框；确认后在虚拟线程运行迁移，对话框内显示阻塞进度。
  - `LOCKED` → 把 `LockView` 追加为 `sceneRoot` 索引 1 的子节点并可见，`mainBorderPane.setDisable(true)`。
- **保留** `stop()` / `setOnCloseRequest` 现有逻辑不动。

### 2.3 `src/main/java/com/raindrop/ui/MainController.java`
- 新增 `@FXML private Button lockButton;` 与 `@FXML public void onLock()`（一行：`SecurityManager.getInstance().lock()`）。
- `installAccelerators()`（80 行）中追加 `KeyCode.L + SHORTCUT_DOWN → onLock`。
- **新增锁定态快捷键屏蔽**：在 `installAccelerators()` 中再装一个 `scene.addEventFilter(KeyEvent.KEY_PRESSED, ev -> { if (SecurityManager.getInstance().isLocked() && ev.isShortcutDown()) ev.consume(); })`。这层过滤器在 accelerator 分派之前运行，能在锁定状态下吞掉所有含 SHORTCUT (Ctrl/Cmd) 的组合键，从而屏蔽 `Ctrl+N` / `Ctrl+W` / `Ctrl+Tab` / `Ctrl+Shift+D` / `Ctrl+,` / `Ctrl+L` 全部应用级快捷键。同时因为 `mainBorderPane.setDisable(true)`，`onAction` 走不到 controller。解锁遮罩内的 `PasswordField` 只依赖普通字符键与 Enter，不受影响。
- 新增 `installActivityFilter()`（在 `installAccelerators` 里调用）：
  ```java
  scene.addEventFilter(Event.ANY, ev -> {
      var t = ev.getEventType();
      if (t == MouseEvent.MOUSE_MOVED || t == MouseEvent.MOUSE_PRESSED
       || t == KeyEvent.KEY_PRESSED   || t == ScrollEvent.SCROLL) {
          IdleWatchdog.get().markActivity();
      }
  });
  ```
  故意用具体事件类型（不用 `instanceof`）避免焦点/布局合成事件误重置。
- 新增 `presentSecurityFlow(Stage)`：状态分派 + `SecurityManager.attachLockListener(this::onLockStateChanged)`。
- 新增 `onLockStateChanged(boolean locked)`：切换 `sceneRoot` 中 `LockView` 的可见性；解锁时 `mainBorderPane.setDisable(false)` 并把焦点还给当前 Tab。
- 新增 `installIdleWatchdog()`：创建 `IdleWatchdog` 并启动；watchdog 内部处理 `timeout=0` / 已锁定的 no-op。
- **不要**触发 `connectionManager.disconnectAll()`。

## 4. SecurityManager 状态机

```
                          [bootstrap()]
                                │
        ┌───────────────────────┴───────────────────────┐
        ▼                                               ▼
   UNINITIALIZED                                     LOCKED
   （无 verifier 行）                              （有 verifier 行）
        │ completeSetup(pwd,hint)                       │ unlock(pwd)
        │  → 派生密钥 → 设 active encryptor              │  → 派生密钥
        │  → MigrationRunner.run (若有遗留数据)           │  → 尝试解密 verifier
        │  → 写 verifier / hint / kdf_version           │  → 常量时间比对
        │  → lockedProperty=false                       │  → 匹配 → 设 active encryptor
        ▼                                               ▼
      UNLOCKED  ◄───────── unlock(pwd) ───────────  LOCKED
        │ lock()（按钮 / Ctrl+L / 空闲触发）              ▲
        │  → 清 active encryptor                         │
        │  → lockedProperty=true                         │
        └────────────────────────────────────────────────┘
```

允许操作矩阵：

| 状态 | encrypt/decrypt | 主 UI 可交互 | 打开新连接 | 已开会话 I/O | 销毁性重置 |
|---|---|---|---|---|---|
| UNINITIALIZED | 抛 | 否（`setDisable`） | 否 | n/a | 否 |
| LOCKED | 抛 | 否（遮罩） | 否 | **保持运行** | 是（解锁屏入口） |
| UNLOCKED | 正常 | 是 | 是 | 是 | 是（设置里修改） |

`SecurityManager` 状态变更仅在 FX 线程；`CryptoUtil` 通过 `volatile` 引用读取当前 encryptor。所有派生 KDF 与迁移工作放到 `TaskExecutor.submit(...)` 虚拟线程。

## 5. 迁移算法（`MigrationRunner.run(Connection c, StandardPBEStringEncryptor newEncryptor)`）

1. `c.setAutoCommit(false)`。
2. 构造两个“旧 encryptor”：
   - `strongLegacy` = `PBEWithHMACSHA256AndAES_256 + 10k iters + password="raindrop-secret-key-2024"`（现存密文的实际编码）。
   - `oldLegacy` = `PBEWithMD5AndDES`（`CryptoUtil` 原本的回退，历史遗留可能仍有）。
3. 对以下 `(表, 列)` 逐行迁移：
   - `connection_profile.password`
   - `connection_profile.key_pass`
   - `credential.password`
   - `credential.key_data`
   - `credential.key_pass`
   
   步骤：`SELECT id, {col}` where 非空 → 先尝试 `strongLegacy.decrypt`，失败则 `oldLegacy.decrypt`；均失败则记录到 `List<FailedRow>` 但不中止。成功则 `newEncryptor.encrypt(plain)` 加入批量 `UPDATE`。
4. 每列执行 `executeBatch()`。
5. 若 `failedRows.isEmpty()`：写 `verifier` / `hint` / `kdf_version` → `commit()`。
6. 否则：`rollback()` → 抛 `MigrationException(failedRows)` → UI 显示：“迁移失败于 N 行 `[table.id]`，未提交任何更改。请选择：重试 / 破坏性重置 / 恢复备份。”
7. `finally { c.setAutoCommit(true); }`。

全新安装数据表为空 → 跳到第 5 步；同一段代码同时覆盖新装与升级两条路径。

## 6. 锁定/解锁 UX — StackPane 遮罩策略

**选定：StackPane 遮罩，不做 `scene.setRoot` 切换。**

理由：
- `TabPane` 内含 `SwingNode` 包装的 JediTermFxWidget；从场景图脱离会触发 AWT peer dispose，重挂载可能崩溃。
- StackPane 保持 TabPane 一直在场景图内，遮罩层作为上层子节点覆盖之。
- **不**动 `Stage.maximizedProperty`，避免 KDE/KWin (X11) 剥除 `_NET_WM_STATE_MAXIMIZED_*`（CLAUDE.md §13.6）。

具体：
- 锁定：`sceneRoot.getChildren().add(lockRoot)`（首次懒加载）或 `lockRoot.setVisible(true)`；`mainBorderPane.setDisable(true)`；`passwordField.requestFocus()`。
- 解锁：移除或隐藏 lockRoot；`mainBorderPane.setDisable(false)`；把焦点还给当前 Tab。
- 遮罩 CSS：`-fx-background-color: rgba(20,20,20,0.98)`（不透明避免看到底层内容）。

**设置对话框**沿用 `MainController.showAsModalDialog` 的 UTILITY + `alwaysOnTop=true` + `mainRoot.setDisable(true)` 模式；**禁用** `initOwner+initModality`。

## 8. 风险与待确认项

1. **JediTermFxWidget + 遮罩焦点交互**：手动验证 §9 的“终端聚焦时手动锁定”。已备兜底：`mainBorderPane.setDisable(true)` 阻断焦点向 Tab 传导。
2. **KDF 强度**：v1 仅 `SHA-256(pwd + pepper)`，非 password-hashing 级；本地桌面场景下可接受，将来可升级到 Argon2id (v2) 通过 `master_password_kdf_version` 迁移。
3. **提示文本明文可见**：用户可能把密码直接写进提示；在设置对话框加一行灰色提示文字警告。
4. **迁移失败 UX**：目前只允许“全部成功或全部回滚”，不允许“跳过失败行”。避免部分数据加密态不一致。请用户在实现阶段最终确认。
5. **修改主密码期间**的并发写：以进度遮罩 + `mainRoot.setDisable` 阻断任何新连接/凭证保存，保证事务窗口内无写入。
6. **`SshSession` mid-connect 与锁定竞争**：`SshSession.connect` 5 处 `CryptoUtil.decrypt` 均在最开始一次性完成，之后本地变量持有明文，读取回路不再走 crypto。已确认安全。

## 9. 端到端验证清单

1. **全新安装**：删除 `~/.raindrop/raindrop.db*` → 启动 → 强制设置密码 → 主 UI 可用 → 设置里默认 timeout=600。
2. **重启解锁**：关闭 → 重启 → 遮罩出现 → 输错 → 停留锁定 → 输对 → 解锁。
3. **升级带旧数据**：拷入预生成的旧数据库 → 启动 → 设置密码完成 → 验证 verifier / kdf_version 已写 + 所有列在新密钥下可解密 → 连一条 SSH 成功。
4. **空闲自动锁**：设 timeout=15s → 15 秒无操作后应在 20 秒内触发 → 中途鼠标移动应重置。
5. **timeout=0**：等 5 分钟不锁。
6. **手动锁**：点 Lock 按钮 / Ctrl+L 立即锁；已锁再按 Ctrl+L 应被吞掉不生效；测试所有其他快捷键（Ctrl+N/W/Tab/Shift+D/,）在锁定态下均无效。
7. **会话存活（关键）**：在真 SSH 里跑 `top` → 锁 → 等 30s → 解锁 → `top` 仍在更新 → 键入生效。
8. **销毁性重置**：解锁屏 “Forgot password?” → 输入 `RESET` → 确认 → `credential` + `connection_profile` 清空 → 回到设置屏。
9. **修改主密码**：解锁 → 设置 → 修改主密码 → 完成 → 重启后旧密码失败、新密码成功、已保存连接仍能连。
10. **锁定态写入阻断**：调试按钮直调 `CryptoUtil.encrypt("x")` → `IllegalStateException`。
11. **最大化状态保持**：最大化 → 锁 → 解锁 → 仍最大化；设置对话框流程重复一次仍最大化。
