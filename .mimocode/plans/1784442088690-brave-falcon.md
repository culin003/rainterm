# 多终端批量命令广播 — 实施计划

## 目标

在主窗口顶部新增一条"Broadcast Bar"，让用户可以把同一条命令一次性发到多个已连接的 SSH tab。基于用户已确认的四条决策：

1. **目标 tab**：广播栏内提供多选（默认全选已连接 tab）；目标数 ≥ 3 时弹确认。
2. **回显**：不做 local echo，依赖服务器 PTY 的 server-echo 让每个 tab 自然显示命令。
3. **回车**：Enter 触发发送，payload 末尾自动追加 `"\r"`。
4. **历史**：进程内内存 100 条，相邻去重，`↑/↓` 循环，不落盘。

### 修改

- **`src/main/java/com/raindrop/ui/TabManager.java`**：新增 record `ConnectedTab(Tab, ConnectionProfile, JediTermFxWidget)` 与 `public List<ConnectedTab> getConnectedWidgets()`；实现为遍历 `tabPane.getTabs()`、交叉 `widgets` / `tabProfile` / `connectionManager.getSession()`，仅返回 `session.isConnected()` 的行；顺序与 TabPane 一致；返回 `List.copyOf(...)` 只读快照。
- **`src/main/java/com/raindrop/ui/MainController.java`**：
  - `@FXML Node broadcastBar` + `@FXML BroadcastBarController broadcastBarController`。
  - `initialize()` 末尾把自身注入 controller，根据 `ConfigManager.getBoolean("broadcast_bar_visible", false)` 决定 `broadcastBar.setVisible/setManaged`。
  - 新 `@FXML onToggleBroadcastBar()` + `installAccelerators()` 增加 `Ctrl+Shift+B`。
  - 切到可见时 `Platform.runLater(() -> broadcastBarController.focusInput())`。
- **`src/main/java/com/raindrop/terminal/SshTtyConnector.java`**：在 `write(byte[])` 上加一把 `private final Object writeLock = new Object();`，`synchronized(writeLock)` 包住 `out.write + out.flush`。`write(String)` 委托到 `write(byte[])` 后自然继承。理由：广播的虚拟线程与用户在同 tab 键盘输入共用同一 OutputStream，不加锁会导致字节交错。
- **`src/main/java/com/raindrop/core/TaskExecutor.java`**：暴露 `public static Executor executor()` 视图，供 `CompletableFuture.supplyAsync(..., executor)` 使用。
- **`src/main/resources/fxml/MainView.fxml`**：顶部 `<VBox>` 里在 QuickConnectBar 之后追加 `<fx:include fx:id="broadcastBar" source="BroadcastBar.fxml"/>`；ToolBar 里新增 `<Button text="Broadcast" onAction="#onToggleBroadcastBar"/>`。

## 二、Broadcast Bar UI 结构

`BroadcastBar.fxml` = 一个 `HBox`（默认 `visible=false managed=false`），从左到右：

- `Label "Broadcast:"` 加粗
- `MenuButton fx:id="targetsBtn" text="Targets: 0/0"` — 展开一个 `CustomMenuItem`，内含 `[Select All / Clear All 两个小按钮, ListView<CheckBox<Tab>>]`；每次展开前刷新，Cell 显示 `profile.name + " (" + host + ")"`
- `TextField fx:id="commandField"` `HBox.hgrow=ALWAYS`，promptText 提示 `"type a command, ↑↓ for history, Enter to send"`
- `Button fx:id="sendBtn" text="Send"`
- `Button text="✕"` 隐藏栏

左侧 3px 强调色边框，避免用户与 QuickConnect Bar 混淆。常驻在 FXML，切换 `visible/managed` 让它不占空间。

## 三、线程模型

```
[FX] onSend()
  ├─ cmd = commandField.getText().strip()
  ├─ if cmd empty → return
  ├─ history.push(cmd); commandField.clear()
  ├─ targets = TabManager.getConnectedWidgets() ∩ selectedTargets 快照
  ├─ if targets empty → showError "No connected targets"
  ├─ if targets.size() >= 3 → 确认 Alert (ThemeManager.apply)
  ├─ sendBtn.setDisable(true)
  ├─ updateStatus("Broadcasting to N tabs...")
  └─ BroadcastService.broadcast(targets, cmd + "\r")
        .whenComplete((result, err) -> Platform.runLater(() -> {
              renderResult(result);
              sendBtn.setDisable(false);
        }));
```

`BroadcastService.broadcast(...)`：每个 target 一个虚拟线程（`CompletableFuture.supplyAsync(..., TaskExecutor.executor())`），并发调用 `connector.write(payload)`；用 `allOf` 等全部完成；返回 `BroadcastResult(List<PerTargetOutcome>)`，每条含 `{tabName, status: OK|DISCONNECTED|ERROR, message}`。

结果呈现：
- 全 OK → 状态栏 `"Broadcasted to N tabs"`。
- 有失败 → 状态栏 `"Broadcast: n ok, m failed"` + 弹一个非阻塞 Alert，列出失败 tab 名和原因。
- 零 target → 直接 showError，不进入服务。

## 四、并发保护

**只在 `SshTtyConnector` 层加锁**，不改 `SshSession`。

- 广播时每 tab 一个虚拟线程，不同 tab 是不同 `SshTtyConnector`，天然互斥。
- 冲突真发生在：广播线程写某 tab 时，用户同时在该 tab 键盘敲字（JediTermFX 也会调 `TtyConnector.write`）。两条并发 write 会让 SSHJ ChannelOutputStream 里的字节交错。
- 一把 `synchronized(writeLock)` 覆盖 `out.write + out.flush`，持有时间 sub-ms，不影响 UI。

## 五、命令历史 & 键位

`CommandHistory` 数据结构：

```
ArrayDeque<String> items;   // 最新在 head
int cursor = -1;            // -1 = 未浏览
CAP = 100;

push(cmd): blank 跳过；等于 peekFirst 跳过；addFirst；超容量 removeLast；cursor = -1
up():   cursor = min(cursor+1, size-1); return items[cursor]
down(): if cursor <= 0 → cursor = -1, return ""；else cursor--, return items[cursor]
resetCursor(): cursor = -1
```

`BroadcastBarController.initialize()` 里 `commandField.setOnKeyPressed`：

- `UP` → `history.up()` 覆盖文本，光标到末尾，consume
- `DOWN` → `history.down()` 覆盖文本，consume
- `ENTER` → `onSend()`, consume
- `ESCAPE` → `history.resetCursor(); onHide()`, consume
- 其他 → 不 consume

`commandField.textProperty()` 加监听器：只要用户手打就 `history.resetCursor()`，避免翻历史后继续输入错位。

## 六、验证

### 手工冒烟（本机 localhost 即可）

1. `sudo systemctl start ssh`；确认 `ssh cooper@127.0.0.1` OK。
2. 在 Raindrop 里建 4 个到 127.0.0.1 的 profile（命名 local-a/b/c/d 便于区分）。
3. 依次打开 4 tab，底部状态栏 `4 active connections`。
4. `Ctrl+Shift+B` 展开广播栏，`Targets: 4/4`。
5. 输入 `echo hello-$$`，Enter → 弹确认（≥3）→ OK。
6. 切每个 tab，确认都看到 echo 回显 + 不同 PID。
7. Case 覆盖：
   - 单 target（勾一个）→ 不弹确认。
   - 让某 tab `exit` → 再广播看到 disconnected 汇总。
   - 广播瞬间在其中一个 tab 手打字符 → 不应出现字节交错。
   - ↑↑↑ 遍历历史；ls+ls 相邻只留一条。
   - 主题切换后广播栏边线仍清晰（不做特殊 CSS，用现有 `-fx-accent`）。

## 七、不在本次范围

- 保存的广播宏（"命名保存 df -h"）：涉及持久化，与"不落盘"策略冲突，后续单独议。
- 多行脚本 / 粘贴 shell 片段：需按行 pace 或 heredoc，本轮只支持单行 + `\r`。
- "排除当前 tab" 开关。
- 广播命令黑名单（`rm -rf /` 二次确认）。
- 审计日志（同样与不落盘冲突）。

## 八、值得沉淀的通用改动

以下三点即使不做广播功能也应做，会被后续多个 feature 复用：

1. `TabManager.getConnectedWidgets()` — 任何跨 tab 聚合操作（广播、批量 SFTP、批量断开）都会用。
2. `SshTtyConnector.writeLock` — 一切"程序主动写"路径都需要它。
3. `TaskExecutor.executor()` 视图 — `CompletableFuture.supplyAsync(fn, executor)` 更好用。
